# 设计决策记录（Design Notes）

## ADR-1：先做「可解释的稀疏检索」，不直接上向量库

**背景**：项目定位是大三/大四学习项目，需要把 RAG 的每一环讲清楚，而不是「调一个框架跑通」。

**决策**：第一版用 BM25 + TF-IDF 混合检索，零外部依赖、离线可跑。

**理由**：
- BM25 可以手写实现（本项目 `BM25` 类约 40 行），便于在复试点讲清楚 IDF、文档长度归一化等概念；
- 检索结果可解释：能看到是哪个词命中的、BM25 与 TF-IDF 各得多少分；
- 不需要下载模型权重，任何机器都能复现评估结果。

**代价**：语义泛化能力弱（口语化表达召回差），因此把向量检索列入了 roadmap 的对比实验。

## ADR-2：两路分数先归一化再加权

**问题**：BM25 原始分是无界的（可能到十几、几十），TF-IDF 余弦相似度在 0~1，直接相加会被 BM25 量纲支配。

**方案**：`bm25_norm = bm25 / (bm25 + 4.0)` 做饱和归一化，再与 TF-IDF 分数按 0.5 / 0.5 融合。

**效果**：融合分数稳定落在 0~1，可以直接用一个阈值做拒答判断，也方便在 UI 上展示。

## ADR-3：加入「查询词覆盖率」作为第二道拒答护栏

**问题**：在小语料上，BM25 的 IDF 会把「能」「一份」这类虚词的权重放大，导致域外问题也能拿到 0.19 左右的分数，**拒答准确率只有 0**。

**实验**（详见下表）：把「查询词覆盖率」作为第二道判断后，域外问题的最高覆盖率明显低于库内问题，拒答准确率提升到 1.000。

| 方案 | Hit@1 | Hit@3 | MRR | 拒答准确率 |
| --- | --- | --- | --- | --- |
| 仅相似度阈值（未扩充停用词） | 0.750 | 0.938 | 0.833 | 0.000 |
| 扩充通用停用词 + 阈值 0.22 | 0.875 | 0.938 | 0.896 | 1.000（配合覆盖率 0.20） |

**补充**：停用词里补充的是一批**通用动词/程度词**（能、做、少、推荐、写……），
它们在任何语料里都不该成为检索依据，属于通用策略而非针对某条测试问题。

## ADR-4：默认抽取式回答，大模型作为可选增强

**理由**：
- 抽取式回答由检索片段里的原句拼成，**可复现、零成本、不会幻觉**，适合做基线和离线演示；
- 大模型回答更像「助手」，但需要 API Key，且在小知识库上更依赖 prompt 约束；
- 两者返回结构完全一致（`Answer`），可以用同一套评估集对比，这也是后续「生成质量评估」的基础。

**容错**：`LLMGenerator` 调用失败（超时、限流、返回异常）时自动回退到抽取式，并在结果里注明原因，Demo 不会因为网络问题挂掉。

## ADR-5：医疗场景必须带护栏

**决策**：
1. 急症关键词（胸痛、言语不清、意识不清、跌倒后不能活动……）命中后，**第一句**提示拨打 120；
2. 涉及用药剂量的提问，提示以医生处方和说明书为准，不做剂量换算；
3. 知识库没有依据时明确拒答，不让模型「自由发挥」；
4. 所有回答都附免责声明。

**理由**：医疗问答的失败代价高，「流畅但错误」的回答比「明确说不知道」更有害。

## 已知局限与后续验证方向

- **口语化召回不足**：把「食盐摄入」问成「吃盐」时，jieba 会把「吃盐」切成一个词，与知识库中的「食盐」「盐」不匹配（实测该问题 Top-1 落在不相关文档）。缓解方向：向量检索、同义词/术语归一化。
- **阈值依赖语料**：`MIN_SCORE` / `MIN_COVERAGE` 是在当前 19 条评估集上校准的，换知识库后需要重新评估。
- **评估集规模小**：只有 19 条，指标波动大；后续需要扩充到 100+ 条并做人工标注。
- **未做生成质量评估**：目前用「关键词覆盖率」作为粗粒度代理指标，后续可以加入忠实度（faithfulness）与相关性评分。
